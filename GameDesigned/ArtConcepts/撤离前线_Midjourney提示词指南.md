# 《撤离前线》美术概念图 - Midjourney提示词指南

## 项目概述

**游戏类型**: 俯视角2D塔防Roguelike"搜打撤"游戏
**美术风格**: 废土科幻 / 低多边形 / 高对比度
**参考作品**: Into the Breach, Brawl Stars, Factorio

---

## 核心风格关键词 (Core Style Keywords)

所有提示词应包含以下基础风格参数，确保视觉一致性：

```
Base Style Parameters:
- isometric view, top-down perspective
- low poly aesthetic, stylized geometry
- post-apocalyptic sci-fi, wasteland theme
- high contrast, bold colors
- clean lines, readable silhouettes
- game asset style, Unity-ready
- industrial mechanical design
- tactical military aesthetic
```

**推荐Midjourney参数**:
- `--ar 1:1` (正方形，适合角色/塔)
- `--ar 16:9` (宽屏，适合环境)
- `--stylize 200-400` (保持风格化)
- `--quality 2` (高质量)
- `--niji 6` 或 `--v 6.1` (根据需要选择)

### 6.2 几何风格指南

**低多边形原则**:
- 角色面数: 500-1500 triangles (3D参考) / 8-16 vertices (2D简化)
- 建筑面数: 200-800 triangles
- 道具面数: 50-200 triangles

**轮廓要求**:
- 所有元素必须有清晰的黑色轮廓线 (2-3像素)
- 轮廓颜色: #1A1A1A 或 #000000
- 内部细节使用高对比度色块区分

**视角规范**:
- 俯视角: 45度倾斜 + 30度俯视
- 等距投影: 严格遵循像素网格
- 避免透视变形，保持正交感

### 6.3 材质表现

**金属材质**:
- 高光: 明确的边缘高光
- 反射: 简化的环境反射色块
- 磨损: 边缘锈迹和划痕细节

**布料材质**:
- 柔和的明暗过渡
- 褶皱用色块表示
- 磨损边缘和补丁细节

**能量材质**:
- 内发光效果
- 渐变色过渡
- 粒子/光晕附加层

### 6.4 统一视觉元素

**必含元素**:
- 所有装备带有废土改装痕迹
- 焊接缝、铆钉、胶带修补
- 警示条纹 (黄黑/红白)
- 发光元件 (能量核心/指示灯)

**禁止元素**:
- 光滑无瑕疵的表面
- 过于复杂的细节纹理
- 写实比例的人体结构
- 过度模糊或发光效果

## 7. Unity技术参数建议 (Unity Technical Specifications)

### 7.1 图像导入设置

**角色/敌人精灵图**:
```
Max Size: 2048x2048 (atlas)
Format: RGBA 32 bit
Compression: None (for pixel-perfect) 或 ASTC 6x6 (mobile)
Filter Mode: Point (no filter)
Pixels Per Unit: 32 或 64 (根据项目设定)
Mesh Type: Full Rect
Extrude Edges: 1-2 pixels
```

**环境瓦片**:
```
Max Size: 1024x1024 (per tile)
Format: RGBA 32 bit
Compression: ASTC 6x6 (mobile) / DXT5 (desktop)
Filter Mode: Point
Pixels Per Unit: 32 或 64
Tile Mode: Continuous (for tilemaps)
```

**UI元素**:
```
Max Size: 2048x2048 (atlas)
Format: RGBA 32 bit
Compression: None
Filter Mode: Bilinear (for smooth UI)
Pixels Per Unit: 100 (Unity UI default)
```

### 7.2 精灵图集规划

**角色图集**:
```
玩家角色: 512x512 per character
- Idle: 4 frames x 4 directions = 16 sprites
- Walk: 6 frames x 4 directions = 24 sprites
- Action: 4-8 frames per action
- Cell size: 64x64 或 128x128

敌人图集: 1024x1024 per enemy type
- Idle: 4 frames
- Walk: 6 frames
- Attack: 4-8 frames
- Death: 6-10 frames
```

**防御塔图集**:
```
每塔: 256x256 或 512x512
- Base: 1 sprite
- Turret: 8-16 rotation frames
- Firing: 4 frames overlay
- Upgrade variants: 3 levels
```

### 7.3 动画帧率建议

| 动画类型 | 帧数 | 帧率 (FPS) | 循环 |
|----------|------|------------|------|
| Idle | 4-8 | 6-8 | Yes |
| Walk | 6-8 | 10-12 | Yes |
| Run | 6-8 | 12-15 | Yes |
| Attack | 4-8 | 12-15 | No |
| Hit | 2-4 | 15-20 | No |
| Death | 6-10 | 10-12 | No |
| Tower Idle | 1 | - | - |
| Tower Fire | 4-6 | 15-20 | No |

### 7.4 分辨率规格

**目标分辨率**:
- 基准: 1920x1080 (16:9)
- 移动端: 1280x720 (16:9)
- 4K支持: 3840x2160

**像素密度**:
- 角色高度: 64-128 pixels (屏幕占比 5-10%)
- 塔防单位: 96-160 pixels
- 小型敌人: 48-80 pixels
- Boss: 256-512 pixels

### 7.5 性能优化建议

**精灵渲染**:
- 使用Sprite Atlas减少Draw Calls
- 启用Sprite Mesh优化透明像素
- 使用Sprite Shape进行地形

**图集策略**:
- 按场景/关卡打包图集
- UI单独图集
- 动态加载非必要资源

**内存预算**:
- 角色图集: 8-16 MB
- 环境图集: 16-32 MB
- UI图集: 4-8 MB
- 效果图集: 8-16 MB

### 7.6 Shader建议

**标准角色Shader**:
```
- Base: Sprite Default
- 添加: Rim Light (边缘光)
- 添加: Color Overlay (受伤闪红)
- 添加: Dissolve (死亡消融)
```

**环境Shader**:
```
- Base: Sprite Default
- 添加: Scroll (流动效果)
- 添加: Tint (天气变化)
```

**UI Shader**:
```
- Base: UI Default
- 添加: Glow (发光效果)
- 添加: Gradient (渐变背景)
```

### 8.1 负面提示词 (Negative Prompts)

建议在所有提示词后添加:

```
--no photorealistic, realistic, high detail, complex textures, 
smooth surfaces, perfect proportions, anime, cartoon, 
watercolor, oil painting, sketch, blurry, low quality, 
asymmetrical, distorted, ugly, deformed
```

### 8.2 风格微调参数

**更卡通化**:
```
增加: --stylize 400-600
添加: cartoon style, exaggerated proportions
```

**更写实化**:
```
减少: --stylize 150-250
添加: semi-realistic, detailed
```

**更简洁**:
```
添加: minimal design, simple shapes, flat colors
减少: --stylize 200
```

### 8.3 批量生成技巧

**保持一致性**:
1. 使用相同的种子值 `--seed [number]`
2. 保持核心关键词不变
3. 只修改主体描述

**变体生成**:
```
原始提示词 + --cref [reference_image_url]
使用角色参考功能保持一致性
```

## 9. 生成工作流程建议 (Workflow Recommendations)

### 9.1 推荐生成顺序

1. **第一阶段**: 环境概念图
   - 确立整体色调和氛围
   - 作为后续资产的背景参考

2. **第二阶段**: 玩家角色
   - 主角是视觉焦点
   - 确定角色风格基准

3. **第三阶段**: 防御塔
   - 与角色风格协调
   - 确保功能识别性

4. **第四阶段**: 敌人
   - 与玩家形成对比
   - 保持威胁感

5. **第五阶段**: UI元素
   - 整合所有视觉元素
   - 确保信息层级清晰

### 9.2 迭代优化流程

```
生成初稿 -> 选择最佳结果 -> 放大优化 -> 
提取关键特征 -> 调整提示词 -> 再次生成 -> 
最终选择 -> 后期处理 -> Unity导入
```

### 9.3 质量检查清单

- [ ] 俯视角是否正确
- [ ] 轮廓是否清晰可辨
- [ ] 色彩是否符合规范
- [ ] 细节是否过度/不足
- [ ] 风格是否一致
- [ ] 尺寸是否合适
- [ ] 动画帧是否足够
- [ ] 是否有遮挡问题
